# Участие в разработке Nomilia

## Стиль кода

Базой служит [coding-style Managarm](https://github.com/managarm/managarm/blob/master/docs/src/contributing/coding-style.md) — Nomilia наследует его полностью: отступы табуляцией в C++, именование `camelCase` для функций и `PascalCase` для типов, `frg`-контейнеры в ядре и серверах.

### Правило комментариев (важно)

Комментарии в коде — **минимальные и только по делу**:

- Никаких больших пояснительных блоков, дублирующих код.
- Комментарий допустим там, где логика неочевидна: трюки с памятью, ABI-контракты, гонки, магические константы протоколов.
- Формат: одна короткая строка — `// делает то-то` или `// почему так, а не иначе`.
- Если фрагмент требует абзаца объяснений — это сигнал рефакторить код, а не писать комментарий.

```cpp
// пример правильного тона
// requeue вытаскивает waitFor'ы напрямую из очереди спящего futex
auto wakeSeq = _sleepQueue.wake(1, [target]{ return target == space; });
```

## Процесс

1. Форк / ветка от `main`, имя ветки: `topic/<краткое-имя>`.
2. Коммиты в стиле Managarm: `подсистема: суть изменения` (например, `posix: add AT_RANDOM to auxv`).
3. Каждый PR решает одну задачу; тесты (`testsuites/`) обновляются, если меняется поведение.
4. Изменения протоколов (`.bragi`) — только аддитивно: новые сообщения, не переиспользование старых номеров.
